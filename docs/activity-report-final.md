### ⭐⭐⭐ 결과물 실제 활용 사례 또는 활용 계획 ⭐⭐⭐

**1) 현업 적용 — 주식회사 에이펙스하이브스트라이크 드론 지식 파이프라인 (운영 중)**
- 예약 작업 9개가 매일 자료를 모은다: 대드론 요격 기술, SBC·온보드 코드, 항법(VIO·SLAM·GNSS 재밍 대응), PX4·ROS 2·MAVLink·QGC 릴리스와 이슈, ArduPilot Lua 변동, 드론 사업공고, 정부 지원사업, 주간 위키 점검, 주간 링크 그래프.
- 자동 수집 자료는 바로 위키에 들어가지 않는다. 디스코드 `수집함`에 올라가고, 사람이 `승인 / 보류 / 제외`한 것만 위키 작성 대상이 된다. 위키 문서도 검증을 거친 뒤 사람이 승인해야 서비스 근거가 된다(수집 승인 + 게시 승인, 두 번의 사람 검토).
- 모든 위키 문서는 한국어로 쓰고, 영문 원문 링크를 맨 위에 두며, 모든 사실·수치에 각주 출처를 단다. 제품 문서는 사양(단위 포함 키), 호환 부품, 용도, 장단점, 추천·비추천 상황을 구조화해 둔다.
- 중간 보고 때의 OpenClaw 크론(텔레그램)은 10월 중순에 이 디스코드 + 예약 작업 구조로 옮겼다.

**2) 최종 결과물 — 드론 엔지니어용 GraphRAG 지식 서비스 (배포 완료)**
- **사용자 화면**: 질문하면 승인된 위키만 근거로 답한다. 답 아래에 근거 자료 목록([n] 클릭 이동), 그래프로 확장된 근거의 관계 경로(예: `MN4014 —제조사→ T-MOTOR`), LangGraph 처리 단계와 걸린 시간을 보여 준다. 분야별 둘러보기(소프트웨어·하드웨어·센서·AI 탐지·대드론·규제·군집·회사)와 검색 4가지(키워드·벡터·키워드+벡터·GraphRAG) 비교 화면이 있다.
- **관리자 화면**: 위키 문서·게시 승인 현황, 수집함(종류별 대기 건수, 승인·보류·제외 버튼), 위키 검토(승인·반려·재검토), 예약 작업 성공·실패와 로그. 맥 로컬 판은 버튼이 볼트의 기존 스크립트를 호출해 문서 상태·파일 이동·디스코드 태그·변경 기록을 함께 바꾼다. 배포판 `/admin`은 비밀번호로 보호된 읽기 전용 스냅샷이다.
- **공개 범위 통제**: 공개 서버와 GitHub에는 승인된 위키만 내보낸다. 원문 사본(저작권), 사내 자료, API 키는 내보내지 않는다.

- **주요 성과 세부내용**

    **주요 성과**

    - 과정의 4단계(지식 구축 → 지능형 검색 → 에이전트 → 서비스 배포)를 실제 운영 데이터로 모두 구현하고 배포했다. 샘플이 아니라 매일 늘어나는 사내 드론 위키(승인 문서 184건)가 데이터다.
    - **GraphRAG의 효과를 숫자로 확인했다.** 같은 27문항(단일 문서 18, 두 문서를 이어 봐야 하는 관계 질문 9)으로 5가지 방식을 RAGAS로 비교했다.

      | 방식 | 충실도 | 답변 관련성 | 문맥 재현율 | 관계 질문 두 문서 모두 찾음 |
      |---|---|---|---|---|
      | 키워드 | 0.933 | 0.592 | 0.593 | 8/9 |
      | 벡터 | 0.913 | 0.532 | 0.537 | 5/9 |
      | 키워드+벡터 | 0.965 | 0.664 | 0.741 | 8/9 |
      | GraphRAG | 0.947 | 0.678 | 0.741 | 9/9 |
      | GraphRAG + LangGraph | 0.952 | 0.711 | 0.741 | 9/9 |

      벡터 검색만으로는 관계 질문의 절반 가까이를 놓쳤고, 키워드를 섞으면 재현율이 0.537 → 0.741로 올랐으며, GraphRAG가 관계선을 따라가 관계 질문을 모두 찾았다. LangGraph 흐름(질문 유형별 답 형식)이 답변 관련성 1위였다.
    - **"근거 없으면 모른다"를 프롬프트 부탁이 아니라 흐름으로 강제했다.** 근거 검사가 ① 없는 자료 번호 인용 ② 단위 붙은 수치인데 인용 없는 문장 ③ LLM이 본 자료에 없는 주장을 찾으면 검색어를 바꿔 다시 찾고, 끝까지 남으면 그 문장을 지운다.
    - **무료 플랜만으로 배포했다.** Render(메모리 512MB) + Neo4j Aura + Gemini 무료 한도. LLM은 Gemini / Claude / 로컬 Ollama 중 설정 하나로 바꿔 끼운다.
    - PRD와 RAGAS 보고서(지표 설명·해석·한계 포함)를 작성해 저장소에 공개했다.

    **도움받은 부분 / 역량**

    - 과정에서 제시된 스택(Neo4j·LangGraph·RAGAS·FastAPI·Docker)을 기존 드론 위키에 맞춰 붙이는 법을 익혔다. 특히 위키의 frontmatter(`manufacturer`, `compatible_with`, `related_products`)가 그대로 그래프 관계선이 된다는 점에서, 지식 베이스를 처음부터 구조화해 둔 것이 GraphRAG의 바탕이 됐다.
    - RAGAS로 "좋아진 것 같다"가 아니라 방식별 숫자로 비교하고, 그 한계까지 적는 평가 습관을 얻었다.

    **어려웠던 점과 극복**

    - **무료 서버 메모리 초과**: 배포 직후 검색만 누르면 서버가 재시작됐다. 측정해 보니 임베딩 모델(25만 토큰 사전)과 토크나이저가 약 880MB를 차지했다(한도 512MB). 우리 문서에 나오는 토큰 + 자주 쓰는 토큰 4.4만 개만 남긴 경량 모델·토크나이저를 직접 만들어 약 350MB로 줄였다. 원본과의 코사인 유사도는 문서 조각 기준 0.997 이상이다.
    - **무료 LLM 한도**: `gemini-3.5-flash`는 무료 한도가 하루 20회라, 답변 1건에 3~6회 호출하는 흐름에서는 하루 몇 건 만에 멈췄다. `gemini-3.5-flash-lite`로 바꾸고 IP당·하루 요청 수를 제한했다. 이 모델이 각주식 인용(`[^1]`)을 써서 근거 검사가 오탐하던 문제도 인용 형식을 맞춰 고쳤다.
    - **배포 플랫폼 변경**: 과정에서 제시된 Hugging Face Spaces가 Docker Space를 유료(PRO)로 바꿔 생성이 거절됐다. 같은 Dockerfile로 Render에 배포했다.
    - **근거 검사 오탐**: 처음엔 제품명 속 숫자(`MN4014`, `KV380`)나 "자료 없음" 문장까지 근거 없는 수치로 잡아 재검색이 반복됐다. 단위가 붙은 수치만 보도록 규칙을 좁혔다.
    - **평가 도구 호환성**: RAGAS가 최신 langchain-community와 충돌해 import가 안 됐다. 호환되는 버전(0.4.1)을 찾아 고정했다.
    - **Neo4j 가용성**: Aura 무료 인스턴스는 오래 안 쓰면 일시정지된다. Neo4j에 연결할 수 없으면 같은 그래프를 파일에서 읽도록 대체 경로를 두고, 화면에 현재 그래프 저장소를 표시했다.

#### ⭐ 활동 소감(좋았던 점, 아쉬웠던 점, 향후 계획 등)

- **(좋았던 점)** 과정의 단계별 스택이 실제 업무 문제에 그대로 맞아떨어졌다. 특히 GraphRAG는 "이 모터에 맞는 프롭·ESC", "같은 제조사의 다른 제품"처럼 드론 부품 선정에서 늘 묻는 관계형 질문에 바로 효과가 있었다. 중간 보고에서 아쉬웠던 "지식은 많은데 근거가 섞인다"는 문제를, 수집 승인 + 게시 승인 두 단계와 승인 문서만 내보내는 구조로 풀었다.
- **(아쉬웠던 점)** RAGAS 평가에서 답변과 채점을 같은 로컬 모델이 했고, 질문을 문서에서 자동 생성해 키워드 검색에 유리했다. 27문항이라 방식 간 작은 차이는 오차일 수 있다. 근거 검사의 재검색 루프는 이번 세트에서 한 번도 돌지 않아, 그 효과는 아직 숫자로 보이지 못했다. 무료 플랜 제약 때문에 배포본은 더 가벼운 LLM과 경량 임베딩을 써서, 로컬보다 답의 깊이가 얕다.
- **(향후 계획)**
    - 위키에 없는 제품·가격을 묻는 질문 세트를 따로 만들어 근거 검사 루프의 효과를 측정하고, 채점 모델을 답변 모델과 분리한다.
    - 외부용 REST API와 MCP 서버(그래프 기반 호환 부품 조회 포함)를 공개한다.
    - 사업공고(RFP) → 부품 구성·소프트웨어 방향·사업계획서 초안으로 이어지는 추천 흐름을 만든다.
    - 중간 결과물(ULog 진단·Canonical 런북)과 이번 위키·GraphRAG를 하나의 지식 서비스로 합친다.

## ▶️ 2026년 개인 활동 성과

- 사내 드론 R&D 지식 플랫폼을 실제로 운영하고 있다. 매일 자동 수집 → 디스코드 승인 → 한국어 위키(출처 각주·원문 링크) → GraphRAG 서비스로 이어지는 흐름이 돌아간다.
- 사람 승인을 코드로 강제했다. 자동 수집 자료는 수집함을 거쳐야 하고, 위키 문서는 승인돼야 서비스 근거가 되며, 공개 서버에는 승인 문서만 나간다.
- 무료 서버 한도에 맞추려고 다국어 임베딩 모델의 사전을 도메인에 맞게 줄이는 방법(ONNX 가중치·Unigram 토크나이저 동시 축소)을 직접 구현했다.
